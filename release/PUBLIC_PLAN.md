# Candidate verification plan

1. Validate the explicit runtime/support allowlist, source import closure, license/notices, checksums and forbidden-content checks.
2. Create a fresh private instance with synthetic identity; check permissions, distinct credentials, startup configuration and no-overwrite behavior.
3. Qualify the actual supported Windows and ARM64 installation paths, trusted TLS identity, source enrollment, persistence and update/rollback.
4. Check scope isolation, read-only APIs, durable recovery, retention gaps, equal-time history paging and replay without historical animation bursts.
5. Measure bounded Pi performance and inspect the dense interface, responsive behavior, keyboard navigation, reduced motion and saved preferences.
6. Apply the maintainer's explicit publication authorization only after independent content/security review and required corrections; push only the sanitized application. Preparation does not substitute for that review.
