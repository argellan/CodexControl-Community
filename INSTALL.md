# Native Windows Community 0.1.0 installation

The EXE contains the application and its Node/Python/DuckDB runtimes. Supported candidate target: Windows x64 on local fixed storage, with the Windows-provided .NET Framework 4.x desktop runtime. No WSL, VM, Linux container, system Python, system Node, Pi, NAS, package-manager step, firewall rule or administrator installation is required by the core local path.

Run the setup EXE. Select local Codex metadata observation explicitly if desired; it is unchecked initially. Setup creates a new per-user app directory and a separate private instance under USERPROFILE/ARGELLAN/CodexControl-Community on validated local NTFS ancestry. It refuses an occupied destination/instance rather than overwriting identity or history. Existing ancestors are checked before extraction or credential generation. Unsafe replacement grants, links/reparse points and untrusted non-root owners are refused; setup does not repair their ACLs. New parents receive the current-user/SYSTEM private DACL. AppData is not the default because application-capability grants there may permit replacement. Existing instances are not moved automatically. Node/Python/DuckDB stay application-local; system PATH and existing runtime installations are unchanged.

Start the installed CodexControl Community launcher. It opens the foreground local observer; stop that console with Ctrl+C. Visit the recorded 127.0.0.1 loopback origin. Use the private owner-access.json in the private instance for initial access; never put it in a URL, source repository or report. Establish an individual password through the existing administrator workflow. No credentials are printed by setup. No logon task/service or network listener is silently installed.

The local archive sender preserves the existing exact-version receipt and pending-row safeguards. Its receiver and immutable closed segments, SQLite catalog and rebuildable DuckDB projection remain on this Windows PC. Archive retry runs at most once per minute with bounded batches; current failed/pending state remains visible. Optional GitHub collection requires explicit existing private configuration; no provider requests occur during installation. Real off-host backup and a complete event disaster-recovery strategy remain separate.

Local fixture qualification uses explicit --install --destination=ABSOLUTE_NEW_TEST_ONLY_APP --instance=ABSOLUTE_NEW_INSTANCE --test-only --no-shortcuts --port=PRIVATE_TEST_PORT arguments. These are isolated test installations, not production deployments. Never reuse those arguments against an installed private instance.

This is a private local-test preview. Mandatory feature/source reconciliation, performance, platform/device and independent release review are not implied by successful setup. Preserve original failures and all fixture evidence.
